# 虚拟货币完整版开发计划

日期：2026-10-20（Asia/Shanghai）

状态：2026-10-20 用户已批准建立 Goal、实施开发并提交至 GitHub `full-version`。执行进度和支持矩阵见 [开发验收台账](../reports/2026-10-20-crypto-full-version-progress.md)。

依据：[功能复核报告](../reports/2026-10-20-crypto-full-version-audit.md)。本计划补充原 `DEV_PLAN.md`，不改写其历史里程碑，也不沿用“M0–M7 已完成，所以全部功能已经验收”的推断。

## 1. 交付目标和边界

完成可复现、可部署到 paper/dry-run、可分别验证交易所适配的虚拟货币主链路：

`已收盘行情 → 多级别缠论/机会/特征 → 样本与模型 → 账户评估 → 部署产物 → 在线信号与订单 → 恢复、对账、监控`

优先支持 Binance USDT 线性永续，其后 OKX USDT 线性永续；现货保留回归支持，反向合约/期权不默认宣称支持。股票功能暂缓，币圈版本完成不要求股票模块先补齐。

约束：

- 保留现有 cbsp/model 扩展接口、用户 GUI、默认配置兼容性与段算法核心。
- 不增加依赖，优先复用现有配置、SQLite、模型适配和订单状态机。
- 通用框架开发与 V29 等冻结研究分支隔离。不得改冻结 DB、策略参数、既有证据，也不得因本计划启动正式回测、OOS、V29 preflight 或绩效读取。
- 已有 V28 v4 研究输入限制持续有效；本计划开发验证使用小型合成数据/明确来源的测试 fixture，不借用旧研究输出构造“正确结果”。
- Inline 串行执行。每个行为修复先观察回归测试失败，再最小修复；每个里程碑按 Lore 留下独立提交和明确验证范围。
- 本计划不包含实盘授权。测试网实际下单也必须遵循既有 candidate/模式/环境门禁与用户授权，不能为“测通接口”伪造正式候选收据。

## 5. C2：建立因果发布与真正的特征对账

主要文件：`Chan.py`、`ChanModel/FeatureEngine.py`、`CustomBuySellPoint/Strategy.py`、`ModelStrategy/FeatureReconciliation.py`、多级别相关测试。

实施：

1. 将 G04 的真实调度复现写成回归测试：1h 已收盘、4h 尚未收盘时，修改 4h 最终 close 不得改变 1h 当时特征。
2. 保留结构计算/图形回放用途，在策略和特征访问边界只提供当时已发布的结构。明确事件的形成时间、确认时间、可用时间，不能只看端点时间。
3. 跨级特征使用最新已完成父周期，或明确的仅由已完成子 K 组成的 provisional 状态；两种语义不能共享同一个特征名称。
4. 审查笔/段/中枢/买卖点的确认与后续重写，历史决策使用不可变快照；不得以比较时忽略易变字段来消除漂移。
5. 将 FeatureReconciliation 扩展为按 instrument/level/decision_time/event_id 对齐，比较信号、特征名/值、分数、退出和去重状态。缺失/额外/顺序错乱/非有限值均应有差异记录。
6. 复用研究分支中已验证的因果思路时单独审查依赖；不整包合并 V29，不修改其冻结实现或证据。

验收：

- prefix-only、全数据后截取、未来 suffix 变异三条路径的历史决策与特征一致。
- 再加“尚未收盘父 K 最终值变异”测试，避免 prefix 一致但共同窥视父 K 的漏洞。
- 4h/1h/15m、做多/做空、首次确认/失效/重建、乱序拒绝均覆盖。
- 既有单级别/多级别结构和绘图测试保持通过；不更改 `Seg/SegListComm.py` 及段算法核心。

## 6. C3：修复训练数据契约并接通在线模型

主要文件：

- `ModelStrategy/backtest.py`、`BacktestChanConfig.py`、`ModelGenerator.py`
- `ModelStrategy/models/{Xgboost,lightGBM,deepModel}/`
- `ChanModel/CommModel.py`、`XGBModel.py`

- `tests/test_m2_features.py`、`test_m3_model.py`；建议新增 `tests/test_model_deployment_contract.py`

实施：

1. 写多币种时间倒置、标签未知误写 0、预测 meta 重排三个失败测试。
2. 样本记录 instrument、decision_time、feature_available_at、label_end_time；按全局 UTC 边界分训练/验证/测试。边界重叠样本按标签观察区间清除，不能仅对数组排序后机械切分。
3. 未观察完整的标签保留 unknown，训练时明确排除并统计；负例只能来自完整观察。
4. 模型保存版本化 meta、特征名称/顺序、缺失值策略、标签定义、训练窗口、代码/配置摘要；预测按训练 meta 对齐，拒绝不兼容版本。对同维但乱序的列必须检测。
5. 复用 `CCommModel` 增加必要的 LGBM/MLP 在线适配，或者在支持矩阵中明确这些模型仅支持离线训练，直至完成接入。
6. 部署配置绑定模型、策略、特征版本和阈值；SignalMonitor/开仓/后验统一加载同一产物。将“候选信号时评分”和“实际突破时评分”的契约明确区分。
7. 默认 CheckOpenScore 使用正确的交易级别和对应已完成周期，不再只取全库最后一行；缺模型/缺特征/版本漂移时禁止新开仓并记录原因。

验收：

- 多币种任意排列不改变 train/validation membership；训练标签结束时间不侵入验证段。
- 交换输入特征列后预测不变，错误 meta 被拒绝；存/取模型结果相等。
- XGB/LGBM/MLP 各自以小合成样本完成训练→持久化→加载→评分；只检验功能，不宣称收益有效。
- 模型版本从样本到信号 DB、订单意图和后验记录一致。
- 同一历史决策用离线与在线路径生成相同特征和分数，缺失证据不能默认放行。

## 11. 风险与不重做的内容

- 时间语义修复会改变历史信号和样本，必须版本化；不能拿旧回测数字作为修复后证据。
